# Automation Orchestrator Instance

Deploy an Automation Orchestrator instance using the AutomationOrchestrator custom resource.

## Overview

This deploys the actual Automation Orchestrator application after the operator is installed. The instance requires:
- Automation Orchestrator operator (installed first)
- PostgreSQL databases (bundled or external)
- Database credential secrets
- AutomationOrchestrator custom resource (generated by aapctl)

## Prerequisites

1. **Operator installed**:
   ```bash
   oc apply -k ../operator/overlays/default
   oc wait --for=condition=ready pod -l control-plane=controller-manager -n automation-orchestrator --timeout=5m
   ```

2. **PostgreSQL databases** (choose one):
   - Deploy bundled PostgreSQL: `oc apply -k ../postgresql/overlays/default`
   - Use external PostgreSQL instance

3. **aapctl CLI** installed for generating manifests

## Overlays

### `default`
Instance-only deployment for use with external PostgreSQL.

**Use when:**
- You have an existing PostgreSQL instance
- Using a managed PostgreSQL service (AWS RDS, Azure Database, etc.)
- PostgreSQL is deployed separately

### `with-postgres`
Complete stack including bundled PostgreSQL and the instance.

**Use when:**
- You want an all-in-one deployment
- Testing or development environments
- Self-contained installations

## Installation Steps

### Step 1: Generate Database Secrets

Use the helper script to generate secrets with random passwords:

```bash
cd automation-orchestrator

# For default overlay (external PostgreSQL)
./scripts/generate-secrets.sh default

# For with-postgres overlay (bundled PostgreSQL)
./scripts/generate-secrets.sh with-postgres
```

**Manual secret creation:**

If you prefer to create secrets manually:

```bash
# Copy templates
cp instance/base/secrets/*.template instance/overlays/default/secrets/

# Remove .template extension and edit
cd instance/overlays/default/secrets/
for f in *.template; do mv "$f" "${f%.template}"; done

# Edit each file and replace REPLACE_WITH_SECURE_PASSWORD
vim orchestrator-pg-credentials.yaml
vim temporal-pg-credentials.yaml
```

**For external PostgreSQL:**

Update the host, port, and other connection details in the secrets:

```yaml
stringData:
  host: "my-postgres.example.com"  # Your PostgreSQL host
  port: "5432"
  database: "orchestrator"
  username: "orchestrator"
  password: "your-secure-password"
  sslmode: "require"  # or verify-ca, verify-full
```

### Step 2: Generate AutomationOrchestrator Custom Resource

Use `aapctl` to generate the full custom resource:

```bash
./scripts/generate-ao-manifests.sh
```

**With custom configuration:**

```bash
./scripts/generate-ao-manifests.sh \
  --set automation-orchestrator-cr.postgres.host=my-postgres.example.com \
  --set automation-orchestrator-cr.postgres.sslMode=require \
  --set automation-orchestrator-cr.replicas=3
```

This generates `instance/base/automationorchestrator.yaml` with all required fields.

### Step 3: Update Kustomization

Uncomment the secret resources in the overlay kustomization:

```bash
# Edit the kustomization file
vim instance/overlays/default/kustomization.yaml

# Uncomment these lines:
#  - secrets/orchestrator-pg-credentials.yaml
#  - secrets/temporal-pg-credentials.yaml
```

Or use sed:

```bash
sed -i '' 's/^  # - secrets/  - secrets/g' instance/overlays/default/kustomization.yaml
```

### Step 4: Deploy the Instance

```bash
# Verify the build first
kustomize build instance/overlays/default

# Deploy
oc apply -k instance/overlays/default
```

**Or for bundled PostgreSQL:**

```bash
kustomize build instance/overlays/with-postgres
oc apply -k instance/overlays/with-postgres
```

### Step 5: Verify Deployment

```bash
# Watch the instance status
oc get automationorchestrator -n automation-orchestrator -w

# Check all pods
oc get pods -n automation-orchestrator

# View instance details
oc describe automationorchestrator automation-orchestrator -n automation-orchestrator
```

Expected pods:
- `automation-orchestrator-api-*` - API server
- `automation-orchestrator-worker-*` - Background workers
- `automation-orchestrator-temporal-*` - Temporal workflow engine
- `automation-orchestrator-ui-*` - Web UI
- `postgresql-0` (if using with-postgres overlay)

## Configuration

### Database Connection

Configured in the database secrets and referenced in the AutomationOrchestrator CR:

```yaml
spec:
  postgres:
    host: "postgresql.automation-orchestrator.svc.cluster.local"
    port: 5432
    database: "orchestrator"
    sslMode: "prefer"  # Options: disable, allow, prefer, require, verify-ca, verify-full
    secret: "orchestrator-pg-credentials"
```

### SSL/TLS for PostgreSQL

For production, use `require` or `verify-full`:

1. **verify-ca** or **verify-full** requires CA certificate:
   ```bash
   oc create secret generic orchestrator-pg-ca \
     --from-file=ca.crt=/path/to/ca.crt \
     -n automation-orchestrator
   ```

2. Update the CR to reference the CA secret

### Resource Requests/Limits

The generated CR includes default resource settings. Customize as needed:

```yaml
spec:
  api:
    replicas: 2
    resources:
      requests:
        cpu: "500m"
        memory: "1Gi"
      limits:
        cpu: "2"
        memory: "4Gi"
```

### Storage for File Uploads

Automation Orchestrator needs S3-compatible storage for file uploads (EDA rulebook projects, etc.):

```yaml
spec:
  fileStorage:
    type: s3
    s3:
      endpoint: "https://s3.amazonaws.com"
      bucket: "my-ao-bucket"
      region: "us-east-1"
      credentialSecretRef: "s3-credentials"
```

Create the S3 credentials secret:

```bash
oc create secret generic s3-credentials \
  --from-literal=access-key-id=YOUR_ACCESS_KEY \
  --from-literal=secret-access-key=YOUR_SECRET_KEY \
  -n automation-orchestrator
```

## Accessing Automation Orchestrator

### Get the Route

```bash
oc get route -n automation-orchestrator
```

### Get Admin Credentials

The operator creates an initial admin user:

```bash
# Get the admin password
oc get secret automation-orchestrator-admin-password \
  -n automation-orchestrator \
  -o jsonpath='{.data.password}' | base64 -d
```

Default username: `admin`

## Upgrading

### Operator Upgrade

The operator automatically manages instance upgrades when you update the operator version.

### Configuration Changes

Edit the AutomationOrchestrator CR:

```bash
oc edit automationorchestrator automation-orchestrator -n automation-orchestrator
```

Or update the generated YAML and re-apply:

```bash
vim instance/base/automationorchestrator.yaml
oc apply -k instance/overlays/default
```

## Using Remote Kustomize Reference

Reference this overlay directly from GitHub:

```bash
# For instance with bundled PostgreSQL
oc apply -k github.com/redhat-cop/gitops-catalog/automation-orchestrator/instance/overlays/with-postgres?ref=main
```

**Note**: You must create secrets locally first, as they are gitignored.

## Troubleshooting

### Instance Not Creating Pods

Check the AutomationOrchestrator status:

```bash
oc get automationorchestrator -n automation-orchestrator
oc describe automationorchestrator automation-orchestrator -n automation-orchestrator
```

Look for status conditions and events.

### Database Connection Errors

Verify secrets exist:

```bash
oc get secrets -n automation-orchestrator | grep pg-credentials
```

Test database connectivity:

```bash
# From within the namespace
oc run -it --rm psql-test \
  --image=registry.redhat.io/rhel9/postgresql-15 \
  --env=PGPASSWORD=$(oc get secret orchestrator-pg-credentials -o jsonpath='{.data.password}' | base64 -d) \
  -- psql -h postgresql -U orchestrator -d orchestrator
```

### Pods CrashLooping

Check pod logs:

```bash
oc logs -l app.kubernetes.io/name=automation-orchestrator -n automation-orchestrator --tail=100
```

Common issues:
- Database migration failures
- Missing or incorrect secrets
- Insufficient resources
- Storage issues

### API Not Accessible

Check the route and service:

```bash
oc get route automation-orchestrator -n automation-orchestrator
oc get svc -l app.kubernetes.io/name=automation-orchestrator -n automation-orchestrator
```

Test from within cluster:

```bash
oc run -it --rm curl-test --image=curlimages/curl -- \
  curl -v http://automation-orchestrator-api:8000/api/health
```

## Cleanup

Remove the instance:

```bash
oc delete -k instance/overlays/default
```

This deletes:
- AutomationOrchestrator custom resource
- All instance pods
- Services and routes
- ConfigMaps

**Note**: Secrets and PostgreSQL data are retained for safety.

To remove everything including PostgreSQL:

```bash
oc delete -k instance/overlays/with-postgres
oc delete pvc -l app=postgresql -n automation-orchestrator
```

## Security Considerations

**Production Checklist:**

- [ ] Use strong, randomly-generated passwords
- [ ] Enable PostgreSQL SSL/TLS (`verify-full` mode)
- [ ] Use Sealed Secrets or external secret management (Vault, ESO)
- [ ] Configure network policies
- [ ] Set appropriate resource limits
- [ ] Enable audit logging
- [ ] Use RBAC to restrict access
- [ ] Regular security updates
